# Database migrations (Alembic)

Schema is managed with [Alembic](https://alembic.sqlalchemy.org/). The database
URL and target metadata come from the app itself (`DATABASE_URL` + the models in
`src/db/sql_db.py`), so migrations stay in sync with the ORM models.

## Local / dev
By default the app creates tables on startup (`AUTO_CREATE_TABLES=true`), so you
don't need to run migrations to get going.

## Managed deployments
Set `AUTO_CREATE_TABLES=false` and apply schema explicitly:

```bash
alembic upgrade head        # apply all migrations (run before starting the app)
```

## Changing the schema
After editing a model in `src/db/sql_db.py`:

```bash
alembic revision --autogenerate -m "describe the change"
# review the generated file in migrations/versions/, then:
alembic upgrade head
```

Review autogenerated migrations before committing — Alembic does not always
capture every change (e.g. some constraint or type edits) correctly.
